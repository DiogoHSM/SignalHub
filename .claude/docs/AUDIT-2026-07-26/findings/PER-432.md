## Sólido

- **Hook trio + race-guard**: `useTenants` segue o padrão `{data, status, reload}` (mais `loadMore`/`loadingMore`), com `genRef` incrementado tanto no fetch inicial (`useEffect`) quanto no `loadMore`, e checagem `gen !== genRef.current` antes de aplicar qualquer resultado assíncrono — proteção correta contra race condition/resposta obsoleta. `apps/console/src/v2/screens/useTenants.ts:126-198`.
- **Read-only confirmado**: `TenantsScreen.tsx` não expõe nenhuma mutação — só filtros (window/sort/search), leitura, e `ctx.drill("tenant", …)` para navegação. Nenhum botão de criar/editar/excluir.
- **Sem XSS via traits**: `keyTraits` é renderizado como texto React puro (`{t.key}: {t.value}` dentro de `<span>`), nunca usado para construir `href`/URL. `TenantsScreen.tsx:57-61`. Consistente com o invariante de que o console não deve montar links a partir de valores de trait.
- **Escopo de leitura no backend**: a rota `GET /query/entities/tenants` (pré-existente, não tocada por este PR) exige `requireHumanUser` e `project_id`/`environment_id` obrigatórios via `parseEntityTenantListFilters` (`apps/api/src/routes/query.ts:1317-1339`, `2279-2299`) — sessão humana e escopo projeto+ambiente confirmados.
- **Client-side sort/load-more é intencional e documentado**: comentário explícito em `useTenants.ts:76` ("the list endpoint has no sort query param") e commit message citam o follow-up PER-446 para paginação server-side. Mesma limitação existe (e é aceita) em `useUsers.ts`, que nem tem `loadMore`/paginação — Tenants na verdade vai além do padrão de Users nesse aspecto. Nenhum aviso na UI sobre o corte, mas isso espelha o padrão já aceito para Users, não é uma regressão nova.
- **Cobertura de testes real, não teatro**: `useTenants.test.ts` cobre loading→ok, erro (com `console.error` mockado), guarda sem projeto/ambiente, sort nas 5 dimensões, search trimming + refetch, loadMore com `limit` crescente e `hasMore` correto, e `reload`. `TenantsScreen.test.tsx` cobre guarda de projeto, loading/error, page head, render+drill de linha, não-drill da linha "Unassigned" (disabled), troca de sort, apply de busca, empty state, e load-more/loading-more. Boa cobertura de estados.
- **Convenções visuais (.sh-*, EmptyHint, PageHead)**: seguidas integralmente — `sh-card`, `sh-row`, `sh-btn`, `sh-input`, `sh-segmented`, `sh-tag`, `sh-mono/muted/faint`, `EmptyHint` para vazio/loading/erro, `PageHead` com título+subtítulo+ações.
- **`hasMore` heurístico**: `raw.length > 0 && raw.length >= limit` pode mostrar "Load more" mesmo quando a página carregada esgota exatamente o total (off-by-one otimista), mas isso apenas gera um round-trip extra que se autocorrige na resposta seguinte — comportamento aceitável, não é um bug de dados.
